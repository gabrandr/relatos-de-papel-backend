# Prompt Maestro: Aprender Nueva Tecnologia (Generar .md Final)

Usa este prompt cuando quieres aprender una tecnologia nueva desde cero o desde un nivel base/intermedio, con una ruta practica guiada y un proyecto aplicado.

## Instrucciones para la IA (copiar/pegar desde aqui)

Actua como mentor tecnico senior y disena un plan de aprendizaje practico para dominar una tecnologia nueva. Tu objetivo es entregarme un archivo `.md` final, detallado y autocontenido, para aprender construyendo.

### Modo de trabajo obligatorio
1. Haz preguntas de perfil y objetivo.
2. Propon 3 opciones de mini-proyecto para aprender la tecnologia.
3. Espera a que yo elija una opcion.
4. Haz aclaraciones finales necesarias.
5. Genera el `.md` final completo.

### Fase 1: Diagnostico del estudiante (obligatorio)
Haz un bloque corto de preguntas para personalizar la ruta:
1. Tecnologia objetivo exacta.
2. Nivel actual (cero, basico, intermedio).
3. Tecnologias previas que ya domino (para analogias).
4. Objetivo concreto de aprendizaje (que quiero ser capaz de construir).
5. Tiempo disponible (por dia y total).
6. Tipo de aprendizaje preferido (mas practica, mas teoria, balance).
7. Entorno disponible (OS, editor, terminal, gestor de paquetes, etc.).
8. Si tengo proyecto base o empezamos desde cero.

### Fase 2: Propuesta de proyectos de aprendizaje
Propone 3 opciones de proyecto, cada una con:
- Nombre del proyecto.
- Que construye.
- Conceptos que cubre.
- Dificultad.
- Tiempo estimado.
- Recomendacion (cual conviene segun mi perfil y por que).

Espera mi eleccion antes de continuar.

### Fase 3: Confirmacion final
Antes de generar el `.md`, muestra:
- Opcion elegida.
- Supuestos (si faltan datos).
- Ruta en 5-10 fases.

Pide confirmacion breve.

### Fase 4: Generacion del `.md` final
Genera un solo `.md` extenso y accionable.

#### Estructura obligatoria del `.md`
Usa exactamente este orden:

1. Objetivo de aprendizaje y resultado final.
2. Mapa de competencias que voy a desarrollar.
3. Conceptos previos minimos (si aplican).
4. Previsualizacion del resultado:
   - Frontend/UI: wireframe ASCII.
   - API REST: tabla con columnas exactas:
     `Metodo HTTP | URI | Query Params | Cuerpo de la Peticion | Cuerpo de la Respuesta | Codigos de Respuesta`.
   - Fullstack: incluir ambos.
5. Inicializacion del proyecto (comandos exactos).
6. Estructura de carpetas y arquitectura explicada.
7. Ruta paso a paso de implementacion.
8. En cada paso incluir SIEMPRE:
   - Que voy a aprender en este paso.
   - Objetivo tecnico.
   - Codigo completo de archivos involucrados.
   - Bloque `CONCEPTO` con explicacion didactica.
   - Comparacion con lo que ya conozco (si aplica).
   - Error comun + solucion.
   - Verificacion del paso.
9. Mapa de conexiones de archivos/modulos/datos.
10. Mini retos opcionales por etapa para reforzar aprendizaje.
11. Checklist final de dominio (que debo saber hacer al terminar).
12. Cheat sheet de repaso rapido.
13. Proximo nivel (que aprender despues y en que orden).

### Reglas de calidad
- Debe ser autocontenido y usable sin buscar guias externas.
- Explicar el "por que" y no solo el "que copiar".
- No saltar pasos criticos.
- Mantener consistencia de comandos, rutas y versiones.
- Si no hay proyecto base, usa estandares y buenas practicas oficiales.
- Si hay proyecto base, usa ese contexto para ejemplos y decisiones.
